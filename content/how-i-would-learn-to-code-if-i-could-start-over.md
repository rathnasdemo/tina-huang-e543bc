*Adapted from the video [How I would learn to code (if I could start over)](https://www.youtube.com/watch?v=MHPGeQD8TvI)*

> **TL;DR:** After coding for five years, this is how I would start over. Learn Python basics fast through hands-on practice, then build small projects you find interesting and keep improving them. After that, learn data structures, algorithms, APIs and how to read documentation. The mindset matters most: favor doing over theory, stay curious, solve your own problems, and stay calm when things break. To go faster, join a community or get a job where you code.

I've been coding for five years now. There were things I did right from the very beginning, but there were also a lot of things I didn't do correctly, and I had to figure them out along the way. So this is the guide I wish I'd had when I was starting off: how I would learn coding if I were to do it all over again.

I'm going to go through my step-by-step approach to learning coding, along with an approximate timeline. I'll recommend some resources and go through how to pick projects, including some example projects. Then I'll talk about the correct mentality, or mindset, as you learn to code. That's something I got really, really wrong at the very beginning, and it actually took me years to adapt to the correct mindset. Finally, I'll share a supercharged tactic to learn to code faster after you've covered the basics.

## Start with Python and cover the basics

*[Watch from 0:52](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=52s)*

My recommended language to start coding in is Python. Python is an extremely beginner-friendly language because it's very versatile and the syntax is very simple to understand. It's also an extremely popular language, so there's great documentation for it and it's easy to get help.

Here are the basics to cover:

1. **Variables.**
2. **Simple data types**, like strings, floats and ints, as well as arrays.
3. **Loops, functions and if statements.**
4. **The concepts of object-oriented programming.**

That should be enough to get you started.

## Resources: learn by doing

*[Watch from 1:26](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=86s)*

In terms of resources, I recommend interactive websites or platforms like freeCodeCamp and Codecademy. This is my preference because you don't have to spend a lot of time downloading everything and setting up your environment, which, by the way, I still think is the hardest part of coding today. They're also very hands-on. You immediately get to implement the things you learned, you get instant feedback, and you know right away whether you got the answer correct or not. I go into a lot more detail about why learning through application is so important for technical things in my video on how to learn technical things, if you want a more in-depth reasoning for this.

If you prefer books or videos, that's totally cool as well. My one piece of advice is that if you do choose to learn through videos or books, make sure you also practice everything you're learning, and you're not just sitting there reading your book, trying to consume that information and remember it. The application is going to be more on you.

## Play around beyond the exercise

*[Watch from 2:28](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=148s)*

Another general piece of advice, regardless of where you're learning from: when you're practicing and implementing, play around with things a little and actually explore outside of what the resource tells you to do.

Here's an example. Say a question tells you to print something, like "hello world." You think, okay, I'm printing hello world, and that's a string data type. So what happens if I put in an int data type? If you try that, you'll realize it actually throws an error. What you have to do is transform that int into a string data type.

That really solidifies the idea of different data types, as well as the fact that functions take specific kinds of data types. I'll go into a lot more depth about mentality later on, but for now I wanted to bring up that exploring and playing around while you're coding is a really good way of solidifying information, and it's also what will make you a better programmer faster.

## How long the basics should take

*[Watch from 3:31](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=211s)*

In terms of timeline, I recommend going through these basics fairly quickly. If you're able to dedicate four hours a day, four proper hours of studying, I think this will take you around two weeks.

You might be thinking, "Wow, that's a pretty short period of time." And yeah, it is. If you've never learned technical things before, you might fall into the trap of wanting to understand every single little detail and taking a bunch of notes about the syntax. That is a big trap, and it's also a mistake I made. Trust me, you'd be wasting a lot of your time. You really need to focus on understanding the fundamental concepts by trying them out yourself, and don't focus too much on the details.

## Your first project

*[Watch from 4:14](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=254s)*

After you've covered these basic topics, it's time to do your first project. Learning to code is all about doing projects, so congrats, you're ready to start your first one.

Some platforms or classes will give you sample projects, so feel free to do those, although I still recommend choosing some of your own projects as well. These are my criteria for choosing your first coding project:

1. **Choose something you find interesting and/or useful.**
2. **Start small.** In fact, don't be afraid to do a project someone has already done. It might actually be quite helpful, because if you get stuck you can reference some of what they did, and that can help unstick you along the way. Just make sure you're not copying code from another resource without understanding it or attempting it yourself first, because that won't help you learn.

## Example projects

*[Watch from 5:02](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=302s)*

Here are some example projects.

- **A random food recommendation system.** This was one of the first projects I did. I'm the kind of person who never knows what I want to eat. So I put all the meals I knew how to cook and usually like eating into an array. There's a random module in Python, and you can call a function that randomly indexes that array, gets the food item and prints it out as a recommendation for what to cook that day. After writing that core function, I made it into a program that could take inputs from the user about what I actually had in the fridge, and I added some logic so it would only recommend recipes containing certain ingredients. This project was great because it was useful to me, and it covered a lot of the basics I had just learned and let me practice implementing them.
- **Simple games.** Games like blackjack and poker are really great for practicing object-oriented programming. You can also do tic-tac-toe or snake, which I think are great because you can display a simple UI. It's pretty exciting because you can actually play your game visually.
- **A scoped-down stock trading bot.** This is a smaller version of what I'm working on right now. My project is a bit more complex, because we're getting the data, doing some logic on it, and then connecting back to the brokerage so we can put in trades. But if you're interested in the stock market and trading in general, you can do a scoped-down version pretty easily. For example, you can have some arrays with the prices of a stock you're interested in, and maybe volatility. Then you can do some logic, like if the average price is equal to this, we should sell or we should buy. You can also use other technical indicators, like RSI.

After that, you might think, wouldn't it be nice if I could actually get the data instead of manually putting it into arrays? That's when you can start learning about the pandas DataFrame, which is for storing tables of data, as well as APIs, which stands for applied programming interfaces. That's when different pieces of software interact with each other. In this case, your code is getting data from another piece of software. And that's how you turn your beginner project into an intermediate or advanced project.

This is a great example of a fundamental concept in learning how to code. You start off with a simple project and you keep iterating on it, making it better and better as you learn more. You become a better programmer, and over time your projects get better and better too.

## How long the first project should take

*[Watch from 7:39](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=459s)*

It's a bit harder to give a timeline for finishing your first project, because, like I said, you can start with something simple and keep building on it. But to build that simple first version from scratch would probably take you around a week or so. So say you learn everything in two weeks, and then you probably have another week or so in which you implement the first version of that project.

## After your first project: data structures, algorithms, APIs and documentation

*[Watch from 8:03](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=483s)*

My advice after finishing your first project is, if you haven't already, to start learning about algorithms and data structures. There are a lot of resources on this, and wherever you learned the basics probably also has a section on them. Data structures come in pretty handy, and I wouldn't be surprised if you've already run into them and learned what they are. These include dictionaries, linked lists, queues, heaps, trees and graphs. I think that's most of them. A fun visual project that really gets you implementing these data structures and algorithms is building a maze and algorithms to solve it.

I also recommend focusing on learning how APIs work. Understanding APIs is really important because a lot of the code you write won't be in isolation. You'll be writing code that interacts with multiple other pieces of software to ultimately create a project that does what you want it to do.

I also recommend spending time learning how to read documentation, because you're going to spend a lot of time reading documentation.

So at this point you've covered the basics, done your first project, and learned about data structures, algorithms and APIs. From here on, it's all about learning more topics and implementing them in more projects. Depending on your interests, you might start looking into web development, app development, or playing around with AI. The world is your oyster, and the possibilities are endless.

## The right mindset for learning to code

*[Watch from 9:28](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=568s)*

Now on to mentality and the correct mindset for learning how to code.

1. **Implementation and application over theory and concepts.** I mentioned this one already. Knowing all the things isn't going to help you that much in doing the things.
2. **Stay curious and explore beyond what a resource prescribes.** I've touched on this too, with the print statement example. That's how you start learning about a lot of other concepts and also understand the concepts you already know more deeply. The best programmers I've met are the tinkerers. They're the people who play around with their code and try a bunch of different things, and that makes them really understand what they're doing. It also reveals topics they can later delve deeper into.
3. **Learn how to solve your own problems when you get stuck.** When you really boil it down, programming is all about problem solving. Ask any programmer, even super experienced ones who've been coding for 10 or 20 years, and Stack Overflow is probably still their best friend. It's a forum-style website where people ask coding questions, and it's the first place you should look when you run into a problem. When I was a beginner, and this is something I notice a lot in beginners, when they run into a problem, like an error message, they don't know what to do and kind of freak out. But oftentimes if you just take that error message and Google it, the first link that pops up is probably from Stack Overflow, and if you read the answers people give, they'll probably tell you what your problem is. Then you can go back and actually solve it.
4. **Get comfortable with not knowing things, stay calm and figure it out.** I'm not kidding when I say that if I write a piece of code and it runs without any errors the first time, I become extremely suspicious that something must have gone wrong. My default assumption is that whatever code I'm running probably has an error in it. But that's okay. I just have to look through it and fix the problem so I eventually get it to work. This is an extremely crucial mindset, because if you freak out and can't deal every time you run into an error, you're going to have a huge problem learning to code and being a programmer in general.

## How to supercharge your learning

*[Watch from 11:40](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=700s)*

After you've covered the basics and maybe done a project or two, I highly recommend finding a community to work on projects together. Or even better, get a job where you code, for example as a software engineer or data scientist, something like that. It lets you learn from experienced programmers, and you'll learn so much just from interacting with them. Plus, it gives you a great boost of accountability, because if you get stuck, you can't just give up. It's literally your job.

## Learning to code never ends

*[Watch from 12:09](https://www.youtube.com/watch?v=MHPGeQD8TvI&t=729s)*

Learning how to code really is a never-ending process. You start with the basics, build your first project, become an intermediate coder at some point, and keep building more projects and learning more things. There's never going to be a time when you say, "All right, I'm a master coder now, I never have to learn anything again." That's literally never going to happen, especially because this field evolves so quickly. There are always new tools being released, and things just keep getting better. If you want to take this further and even build a career out of coding, that's something you need to embrace: embrace the learning process and embrace making projects.

For myself, I have to say learning how to code is one of the best decisions I've ever made. It's such a powerful tool to have in your toolbox in our day and age. It's also given me a lot of freedom. If I'm interested in a certain project or just curious about something, it's easy for me to go do it myself because I know how to code. I don't need to rely on other people to do the implementation for me.

I hope this is helpful, gets you more excited about coding, and gives you a path to get started learning the basics and doing your first project.
